# AliProfi Optimizer

Лёгкая замена тяжёлым «оптимизаторам» для WordPress на серверах **OpenResty / Nginx + PHP-FPM + Redis**.
Плагин делает клиентскую оптимизацию, умеет сбрасывать серверный FastCGI-кэш и имеет собственный файловый
страничный кэш для шаред-хостинга, где каталог Nginx недоступен из PHP.

## 📝 Описание

Плагин умеет отдавать готовый HTML из `wp-content/cache/aliprofi-optimizer/pages` ещё до загрузки WordPress.
Для этого при активации создаётся каталог, устанавливается `advanced-cache.php` и, если нужно, добавляется
`define( 'WP_CACHE', true );` в `wp-config.php`. Чужой `advanced-cache.php` не перезаписывается.

На некэшированном запросе плагин:

- откладывает выполнение JavaScript до первого действия пользователя (задерживается всё, кроме списка исключений);
- добавляет `defer` скриптам, при необходимости грузит CSS асинхронно и убирает мусор WordPress из `<head>`;
- снимает `loading="lazy"` с первого крупного изображения и ставит `fetchpriority="high"`;
- подменяет iframe YouTube лёгким превью;
- переносит Google Fonts в локальный кэш и выводит `preload` для `.woff2`;
- сбрасывает файлы FastCGI-кэша OpenResty по permalink, главной и архивам при изменении контента;
- ставит очищенные URL в очередь и прогревает кэш в фоне порциями по WP-Cron;
- чистит базу данных от ревизий, авто-черновиков, корзины, спама и транзиентов, при желании — по расписанию.

Собственный страничный кэш работает только для гостевых GET-запросов без query. Авторизованные, корзина
WooCommerce, комментаторы, предпросмотр, 404, ленты, REST, cron и служебные URL обслуживаются WordPress как обычно.
Для авторизованных пользователей, админки, AJAX/REST/cron, лент, 404, предпросмотра и `DONOTCACHEPAGE`
остальные модули также полностью отключены.

## 🔧 Возможности

| Модуль | Что делает |
| --- | --- |
| Страничный кэш | Готовый HTML в `wp-content/cache/aliprofi-optimizer/pages`; отдача через `advanced-cache.php` до WordPress. Только гостевые GET без query, TTL 1–168 ч, исключения по пути, обход по кукам авторизации/корзины/комментатора. |
| FastCGI purge | `save_post`, `transition_post_status`, удаление записи, комментарии, меню. Файловая очистка и/или HTTP `PURGE`. В админ-баре — меню «Очистить» с пунктами «Весь сайт» и «Эту страницу»; полная очистка также доступна в настройках. |
| Предзагрузка кэша | Очищенные URL попадают в очередь и запрашиваются в фоне по WP-Cron: без cookies, с проверкой хоста и порта, порциями 1–5 URL, с блокировкой от параллельных запусков. При полной очистке можно дополнительно прогревать главную и последние изменённые записи. |
| Delay JS | Задерживаются **все** скрипты, кроме исключений (`jquery`, `jquery-migrate` по умолчанию). Тег получает `type="delayed-script"`, `src` уходит в `data-delayed-src`. Запуск — по `mousemove / scroll / touchstart / keydown / click` или по таймеру 7 с (настраивается). Есть безопасный режим с исключением `wp-content`/`wp-includes`. Загрузчик — 721 байт. |
| Defer | `defer` скриптам, кроме `async`/`defer`, модулей и списка исключений (по умолчанию jQuery). |
| CSS и MediaElement | Асинхронная загрузка CSS (`preload` + `onload`, с `noscript`-фолбэком) и отключение стилей/скриптов MediaElement. Обе опции выключены по умолчанию. |
| Очистка head | `wp-emoji`, `wp-embed`, `rsd_link`, `wlwmanifest_link`, `wp_generator`, `wp_shortlink`. |
| Изображения | Исключения из LazyLoad по классу/имени файла; первое крупное изображение контента — без `lazy` и с `fetchpriority="high"`. Опционально `width`/`height` из метаданных вложения. |
| YouTube | `<div class="yt-facade">` с превью `hqdefault.jpg` и SVG-кнопкой; iframe с `autoplay=1` создаётся по клику/Enter/Space. |
| Google Fonts | CSS и `.woff2` скачиваются в `wp-content/cache/aliprofi-optimizer-fonts/`, внешняя ссылка подменяется локальной, добавляется `font-display: swap`. Preload — по списку в настройках. |
| База данных | Ревизии, авто-черновики, записи в корзине, спам и удалённые комментарии, транзиенты, `OPTIMIZE TABLE`. Счётчики, очистка по кнопке и WP-Cron daily/weekly/monthly. |
| PageSpeed & AI | Анализ скорости мобильной и десктопной версии через Google PageSpeed Insights API v5 (Core Web Vitals, метрики FCP/LCP/CLS/TBT, аудит возможностей) и AI-диагностика узких мест через DeepSeek API с практическими рекомендациями. |

## 🛠 Требования

- PHP 8.1+ (проверено на 8.6), WordPress 6.4+.
- Запись в `wp-content` для собственного страничного кэша и `advanced-cache.php`.
- Для автоматического включения кэша — запись в `wp-config.php`. Если файл защищён от записи, добавьте
  `define( 'WP_CACHE', true );` вручную до строки `/* That's all, stop editing! */`.
- OpenResty или Nginx с `fastcgi_cache` — необязательно, только для очистки серверного кэша.
- Запись в каталог кэша для пользователя PHP-FPM — **только** если выбрана файловая очистка FastCGI.
- Без Composer, внешних библиотек и React/Vue в админке.

## 📦 Установка

1. Скопируйте папку `aliprofi-optimizer` в `wp-content/plugins/` (или загрузите ZIP через «Плагины → Добавить новый»).
2. Активируйте плагин. Создаётся автозагружаемая опция `aliprofi_optimizer`, каталог
   `wp-content/cache/aliprofi-optimizer/`, drop-in `wp-content/advanced-cache.php` и при возможности
   `WP_CACHE` в `wp-config.php`.
3. Откройте **Оптимизатор** в левом меню админки. Настройки разложены по вкладкам: «Кэш», «JavaScript», «Медиа», «База данных», «Шрифты».

Если на сайте уже стоит другой кэш-плагин со своим `advanced-cache.php` (WP Rocket, LiteSpeed и т. п.),
плагин не перезаписывает его и показывает предупреждение. Отключите чужой кэш перед включением своего.

## 🗂 Собственный страничный кэш

Он не требует доступа к каталогу Nginx и рассчитан на шаред-хостинг.

- **Где лежит:** `wp-content/cache/aliprofi-optimizer/pages/ab/cd/<md5>.html`; ключ — `md5(host|путь)`.
- **Как отдаётся:** `wp-content/advanced-cache.php` подключается WordPress при `WP_CACHE=true` и отдаёт файл
  до загрузки плагинов, темы и базы данных. Заголовок `X-Aliprofi-Cache: HIT` подтверждает попадание.
- **Что кэшируется:** только `GET` без query, ответы `200 text/html`, без `Set-Cookie`, `private`, `no-store`
  и `Vary: Cookie/User-Agent/*`. Админка, REST, cron, CLI, 404, ленты, поиск, предпросмотр и `DONOTCACHEPAGE`
  не кэшируются. Запросы с куками `wordpress_logged_in_*`, `wordpress_sec_*`, `wp-postpass_*`,
  `comment_author_*`, `woocommerce_*`, WPML обходят кэш.
- **Время жизни:** 1–168 часов. Файл старше TTL не отдаётся и пересобирается при следующем госте.
- **Исключения:** список путей в настройках, совпадение по подстроке (`/cart`, `/checkout`, `/my-account`).
- **Очистка:** запись, комментарий, меню, архивы, рубрики и метки удаляют соответствующие файлы; кнопки
  «Очистить весь кэш» и «Очистить кэш страниц», а также пункт админ-бара «Очистить» очищают и FastCGI-кэш,
  и собственный. После очистки URL снова ставится в очередь прогрева.
- **WP_CACHE:** плагин добавляет `define( 'WP_CACHE', true );` в `wp-config.php` атомарной записью, если
  константы ещё нет. Существующий `false` не переопределяется. При отключении плагина drop-in удаляется,
  но строка `WP_CACHE` остаётся — её можно удалить вручную.
- **Чужой drop-in:** если `wp-content/advanced-cache.php` создан другим плагином, он не перезаписывается.
  Статус на вкладке «Кэш» покажет конфликт.

На shared-хостинге PHP обычно не видит `/var/cache/nginx/fastcgi`, поэтому собственный кэш — основной вариант.
Если перед PHP всё же стоит `fastcgi_cache`, сервер может отдавать свой HIT раньше `advanced-cache.php`:
тогда либо настройте его очистку, либо отключите серверный кэш для этого сайта.

## 🧩 Конфигурация OpenResty / Nginx

Плагин по умолчанию рассчитан на такую схему:

```nginx
# http { ... }

# Каталог, уровни и зона кэша
fastcgi_cache_path /var/cache/nginx/fastcgi
    levels=1:2
    keys_zone=WP:100m
    inactive=60m
    max_size=2g
    use_temp_path=off;

# PURGE-запросы должны попадать в тот же ключ, что и GET:
map $request_method $cache_method {
    PURGE   GET;
    default $request_method;
}

fastcgi_cache_key "$scheme$cache_method$host$request_uri";

# Кого не кэшируем (дублирует отключение плагина для авторизованных)
map $http_cookie $skip_cache {
    default                        0;
    "~*wordpress_logged_in"        1;
    "~*comment_author"             1;
    "~*wp-postpass"                1;
    "~*woocommerce_items_in_cart"  1;
}

map $request_uri $skip_cache_uri {
    default                     0;
    "~*/wp-admin/"              1;
    "~*/wp-login\.php"          1;
    "~*/wp-json/"               1;
    "~*/xmlrpc\.php"            1;
    "~*[?&]preview="            1;
    "~*sitemap"                 1;
}

server {
    listen 443 ssl http2;
    server_name example.com;
    root /var/www/example.com;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;

    # Очистка (нужен модуль ngx_cache_purge: nginx-extras / libnginx-mod-http-cache-purge)
    location ~ /purge(/.*) {
        allow 127.0.0.1;
        allow ::1;
        # allow 203.0.113.10;  # IP сервера, если PURGE идёт на внешний адрес
        deny all;

        fastcgi_cache_purge WP "$scheme$cache_method$host$1$is_args$args";
    }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;

        fastcgi_cache WP;
        fastcgi_cache_valid 200 301 302 60m;
        fastcgi_cache_bypass $skip_cache $skip_cache_uri;
        fastcgi_no_cache    $skip_cache $skip_cache_uri;
        fastcgi_cache_use_stale error timeout updating http_500 http_503;
        fastcgi_cache_lock on;
        fastcgi_cache_lock_timeout 5s;
        fastcgi_ignore_headers Cache-Control Expires Set-Cookie;

        add_header X-FastCGI-Cache $upstream_cache_status always;
    }
}
```

Проверка: `curl -I https://example.com/` → `X-FastCGI-Cache: HIT`,
`curl -X PURGE https://example.com/purge/` → `204 No Content`.

### Соответствие настроек плагина и Nginx

| Плагин | Nginx |
| --- | --- |
| Каталог кэша | путь из `fastcgi_cache_path` |
| Уровни | `levels=1:2` |
| Ключ кэша | `fastcgi_cache_key`; `{scheme}{method}{host}{uri}` = `"$scheme$cache_method$host$request_uri"` |
| HTTP PURGE | `https://example.com/purge` (плагин добавит URI страницы) |

`map $request_method` обязателен: без него PURGE-запрос даст ключ с методом `PURGE` и не совпадёт с `GET`.
Если ваш ключ содержит `$request_method` напрямую (без `map`), используйте файловую очистку.

Файловая очистка повторяет раскладку Nginx: имя файла — MD5 ключа, подкаталоги берутся с конца хеша
(`/cache/c/29/b7f54b2df7773722d382f4809d65029c` для `levels=1:2`). Плагин пробует и «хвостовую», и «головную»
раскладку, поэтому переживёт нестандартный `levels`.

### Права доступа

Файлы создаёт Nginx, а удаляет PHP-FPM. Если это разные пользователи, файловая очистка не сработает.

```bash
# общий пользователь (типовая связка nginx + php-fpm под www-data)
sudo chown -R www-data:www-data /var/cache/nginx/fastcgi

# или общая группа и setgid на каталогах
sudo chgrp -R www-data /var/cache/nginx/fastcgi
sudo chmod -R g+ws /var/cache/nginx/fastcgi
```

Альтернатива без прав на диск — способ «HTTP PURGE» (нужен `ngx_cache_purge`).
Состояние каталога видно на странице настроек.

## 🚀 Производительность и критерии приёмки

- Попадание в собственный страничный кэш отдаёт статический HTML до WordPress: без PHP-модулей, темы и SQL.
- Промах кэшируется после рендера; накладные расходы — буферизация HTML и одна запись файла.
- Настройки читаются одним `get_option` из автозагружаемой опции → **0 SQL** на фронтенде.
- Модули не обращаются к БД: шрифты — файловый кэш, YouTube/JS/изображения — только строковые операции.
- Исключение — опция «Добавлять width/height»: для картинок без размеров нужен `wp_get_attachment_metadata()`
  (один запрос к postmeta на уникальное вложение, с кэшем на запрос). По умолчанию выключено.
- Очистка БД работает только в админке и по cron: счётчики считаются при открытии вкладки, на гостевые запросы SQL не добавляется.
- Загрузчик Delay JS — 721 байт, стили YouTube — ~430 байт.
- Время работы модулей на некэшированном запросе — единицы миллисекунд; буферизация Delay JS пропорциональна размеру HTML.

Как измерить в Query Monitor: по умолчанию плагин отключён для авторизованных. Для замера временно добавьте
в `wp-config.php`:

```php
define( 'ALIPROFI_OPTIMIZER_FORCE', true );
```

Откройте страницу как гость/админ с Query Monitor и убедитесь, что число запросов не выросло.
После замера константу удалите.

## 🔄 Жизненный цикл

- **Активация** — создаётся `wp-content/cache/aliprofi-optimizer/`, свой `advanced-cache.php`; при возможности
  добавляется `WP_CACHE` в `wp-config.php`. Чужой drop-in не затрагивается.
- **Деактивация** — удаляются свой каталог кэша, drop-in, кэш шрифтов и задания WP-Cron. FastCGI-кэш OpenResty
  не затрагивается; строка `WP_CACHE` в `wp-config.php` остаётся.
- **Удаление плагина** — удаляются опция `aliprofi_optimizer` (на всех сайтах сети), свой страничный кэш,
  drop-in, кэш шрифтов, очередь и блокировка прогрева.

## ⚠️ Примечания

- Собственный страничный кэш рассчитан на гостевые страницы. Куки авторизации, `wp-postpass`, комментатора,
  WooCommerce и WPML всегда обходят его, поэтому персональные страницы не смешиваются.
- `WP_CACHE` и `advanced-cache.php` — общий механизм WordPress. Если его уже использует другой кэш-плагин,
  свой drop-in не устанавливается; сначала отключите чужой кэш.
- Автоматическая правка `wp-config.php` выполняется только при отсутствии `WP_CACHE`. Если файл недоступен
  для записи, добавьте `define( 'WP_CACHE', true );` вручную; статус на вкладке «Кэш» подскажет.
- При отключении плагина строка `WP_CACHE` не удаляется: она безвредна и может использоваться другим кэшем.
- Если перед PHP стоит серверный `fastcgi_cache`, он может отдавать свой HIT раньше `advanced-cache.php`.
  Тогда настройте очистку FastCGI или отключите серверный кэш для сайта.
- `$scheme` в ключе Nginx должен совпадать с фактическим протоколом сайта. Если TLS терминируется на балансировщике,
  настройте `$scheme`/`fastcgi_param HTTPS` так, чтобы ключ был одинаковым для GET и PURGE.
- `$host` берётся без порта; для нестандартного порта ключ нужно скорректировать вручную.
- Первый гостевой запрос с Google Fonts скачивает CSS и `.woff2` (единицы файлов, таймаут 8 с). Дальше — статика.
  CSS обновляется раз в 7 дней; кнопка «Очистить кэш шрифтов» сбрасывает немедленно.
- `defer` не применяется к скриптам с `async`/`defer`, модулям и исключениям. Если тема ломается, добавьте handle/файл в исключения.
- Асинхронный CSS подключает стили через `preload` + `onload` и оставляет `<noscript>`-фолбэк. Это убирает блокировку отрисовки, но может дать мигание вёрстки; при строгом CSP `onload` может не сработать. Исключите главный стиль темы, если вёрстка прыгает.
- Отключение MediaElement убирает стили и скрипты плеера WordPress (`mediaelement`, `wp-mediaelement`). Включайте только если на сайте нет аудио и видео.
- Delay JS задерживает все скрипты, кроме исключений; `application/ld+json`, `importmap` и другие не-JS типы не трогаются. Если вёрстка или интерактив ломаются, включите «Безопасный режим» либо добавьте скрипт в исключения.
- Очистка БД необратима: перед первым запуском сделайте резервную копию. За один запуск обрабатывается до 500 записей/комментариев и 500 транзиентов; при большом объёме повторите.
- `OPTIMIZE TABLE` применяется только к таблицам не-InnoDB со свободным местом — как в WP Rocket; на полностью InnoDB-базе пункт может показывать 0.
- Автоочистка БД использует WP-Cron и запускается при посещениях сайта. На малопосещаемых сайтах настройте системный cron на `wp-cron.php`.
- Предзагрузка кэша тоже работает через WP-Cron и может не запуститься на сайте без посещений. Запросы прогрева идут только на текущий хост и порт, без cookies; предпросмотры и сторонние адреса отбрасываются. Очередь ограничена, параллельные запуски блокируются на 5 минут. Прогрев наполняет и свой страничный кэш, и FastCGI-кэш, если он включён.
- Автоочистка при сохранении меню удаляет весь кэш — меню обычно выводится на всех страницах.

- **1.4.2** — асинхронная загрузка CSS (`preload` + `onload` с `noscript`-фолбэком и списком исключений) и опция отключения MediaElement; обе выключены по умолчанию.
- **1.4.1** — статус страничного кэша показывает точный путь к `wp-config.php` и готовую строку `define( 'WP_CACHE', true );`, если файл недоступен для записи PHP или константа уже упоминается в нём.
- **1.4.0** — собственный страничный кэш в `wp-content/cache/aliprofi-optimizer/`: drop-in `advanced-cache.php`, автоматическое включение `WP_CACHE`, HTML до загрузки WordPress, TTL, исключения по пути, обход по кукам, очистка при изменении контента и прогрев через очередь. Чужой `advanced-cache.php` не перезаписывается.
- **1.3.0** — безопасная предзагрузка кэша: очередь очищенных URL, порционный прогрев по WP-Cron, лимиты, блокировка и проверка хоста/порта; опция прогрева последних записей при полной очистке.
- **1.2.1** — пункты сброса кэша объединены в выпадающее меню «Очистить»: «Весь сайт» и «Эту страницу».

- **1.1.1** — уведомления перенесены под шапку страницы и получили собственный стиль с кнопкой закрытия; бегунок тумблера выровнен по центру; сохранение и кнопки приведены к единому оранжевому стилю; мелкие правки отступов и наведения на строки.
